# S-17 — Additional codegen targets

> Part: Studio · Phase: 7 · Stages: garden · Depends on: S-01, S-13, S-26 · Status: ready

## Goal
A project can also be generated as a **Vue (Vite)** or **Angular** app. The universal layer generates the same way for every target; each target adds its own framework layer schema, node set for the logic canvas (Vue: refs, computed, composables; Angular: signals, services, DI) and codegen.

## Scope
- In: target plugin API hardening; Vue and Angular targets for the universal layer; framework layer schemas and node registries for both; a conformance suite every target must pass; target choice enabled in project creation and settings.
- Out: porting existing React logic (S-27); React Native (M-03).

## User stories
- **US-1** `[garden]` As a user, I can add Vue or Angular as a target and Compact my project's UI to it, so that I'm not tied to React.
  - Acceptance: pages, blocks, bodies and themes generate a runnable Vue or Angular project that looks the same as the React one.
- **US-2** `[garden]` As a user, each added framework has its own Logic canvas with its own node set, so that I use that framework's concepts.
  - Acceptance: the Logic workspace has a framework switcher; Vue and Angular graphs generate idiomatic code.
- **US-3** `[garden]` As a developer, every target passes the same conformance suite, so that targets stay equivalent.
  - Acceptance: one sample set of projects is generated by all targets and checked for structure and visual parity.

## Risks and open questions
- Angular's project structure (modules vs standalone components, signals) changes fast; pin a version.
- Visual parity between targets depends on the shared frame → CSS mapping (S-01).

## Done when
- [ ] The sample projects generate and run in React, Vue and Angular with the same look.
