WibeBlock plan map

You lay out the frames and the AI fills the bodies. Compact then exports a project you own. This map shows how the system is built, the order of work, and every epic in the plan with its dependencies. The plan is a direction, and it changes as development goes on.

Core idea

The user owns the frame, the AI owns the body

Frame (user): the block tree, flex/grid layout, sizing (fixed / fill / hug), and a mobile override for each block. The AI can only propose changes, which you accept or discard.

Body (AI): HTML and Tailwind generated from the block prompt inside the frame. You can edit it, regenerate it, or eject it into child blocks. It goes stale when the style guide in the knowledge base or the skills change. Marked elements become ports that logic can bind to.

Theme: design tokens as CSS variables. Changing a token restyles every block live, with no regeneration. Compact turns the universal JSON plus the React logic layer into a React project (Vue, Angular and React Native later).

Studio · planned 2026-10-28

The Studio

The Studio is where users build their apps. It has two canvases: a design canvas that renders the page from the project data at any device width, and a logic canvas where behaviour is built as blueprint-style graphs bound to the blocks. A new page starts as a random arrangement of empty, pastel blocks, each waiting for a prompt. Every AI change arrives as a proposal to accept or discard. It ships in four stages, and the platform track starts right after the first one.

Stages

Phase 1 · Studio only

alpha

Schema and JSON Schema export, adapters, Runner storage and AI proxy, design canvas with block frames and viewports, random starter layout, Structure panel, inspector, one AI task with proposals, undo.

Done whenA block's body is generated, accepted and undone, and the project is saved on disk as valid JSON the backend can validate.

Phase 2 · alongside Platform foundation

MVP

Shuffle, Files panel, theme studio, knowledge base and style guide, history with AI-turn revert, run preview, Compact; minimal logic canvas (optional).

Done whenA two-page app is designed, checked in the run preview and exported to a folder that runs with no WibeBlock dependency.

Phase 3 · alongside Platform connected

v1

AI themes, global prompt bar with layout proposals, logic v1 (data, lists, forms, context), prompt library, Developer panels, snapshots, assets, Claude Code, onboarding.

Done whenA page is arranged by the AI through a reviewed proposal and a data-driven app is built on the logic canvas.

Phase 7 · picked freely

garden

Photoshop-style layers and pro tools, Vue and Angular targets, framework porting, the AI's own knowledge base, VS Code, browser-only.

Done whenEach epic stands on its own.

Interface sketch

A sketch of the agreed layout, not a final design. The starter layout is random: press Shuffle, or reload the page, to get a new one. Hover a block to see its border buttons, switch viewports to see zoom-to-fit, and switch workspaces at the top.

    Style guide

    Calm and botanical. Lots of white space, rounded shapes, one strong green. Headlines in a soft serif, body in a plain sans.

    • Use the main colour for actions only.
    • Photos of real plants in real rooms; no stock illustrations.
    • Write like a friendly plant shop owner.

    • Workspaces

      Design, Logic, Theme, Knowledge and Preview; page, selection, viewport and zoom live in the URL.

    • Prompt bar

      A command with a scope: the selection in the MVP, the page or the project in v1.

    • Viewport and export

      Phone to 4K at the real width, zoomed to fit; Export runs Compact.

    • Structure and Files

      The page's component hierarchy, and the project's folders: pages, components, images, themes, notes.

    • Starter blocks

      Random sizes and arrangement in a pastel palette, always a real flex layout; each empty block holds only a prompt input.

    • Border buttons

      Generate, add, duplicate, more: they sit on the block's border on hover and stay a fixed size at any zoom.

    • Generated block

      Takes its new style inside and keeps its border; Accept or Discard the proposal. The inspector shows only with a selection.

    • Shuffle and frames

      Shuffle makes a new starter layout; Frames hides borders and buttons to judge the clean result.
