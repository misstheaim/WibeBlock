WibeBlock plan map

You lay out the frames and the AI fills the bodies. Compact then exports a project you own. This map shows the four plan parts, their features, all epics with dependencies and phases, and how the system fits together. The plan is a direction, and it changes as development goes on.

Core idea

The user owns the frame, the AI owns the body

page root · flex column
header · flex row · fill
bodyLogo and nav links, generated from "minimal top bar"
bodySign-in button
hero · leaf · hug
body · staleHeadline, subtext and call to action, from "bold launch hero, dark"

Frame (user): the block tree, flex/grid layout, sizing (fixed / fill / hug), and a mobile override for each block. The AI never changes it.

Body (AI): HTML and Tailwind generated from the block prompt inside the frame. You can edit it, regenerate it, or eject it into child blocks. It goes stale when the global prompt or skills change.

Theme: design tokens as CSS variables. Changing a token restyles every block live, with no regeneration. Compact turns the framework-neutral JSON into a React project (Vue, Angular and React Native later).

Cloud
